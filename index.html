CSE422: Artificial Intelligence
Project Title: Predicting the Severity of Depression using Machine Learning Models

The objective of this project is to analyze surveyed data on depression and apply machine learning models that can predict the severity of depression levels based on various parameters such as demographic, academic and psychological factors. In order to classify, a full pipeline including data preprocessing, learning models, and performance evaluation is implemented. By applying supervised and unsupervised learning techniques, this project attempts to identify important patterns in student mental health data and compare the performance of different machine learning algorithms.

Model Training & Testing:

• Logistic Regression (with class balancing to reduce bias from class imbalance)
• Random Forest Classifier (implemented tree-based ensemble; scaling not required)
• Gaussian Naive Bayes
• K-Nearest Neighbors (KNN) (implemented required scaling)
• Neural Network (MLPClassifier) with hidden layers (64, 32, 16) using ReLU activation and Adam optimizer. Early stopping enabled to reduce overfitting.

Model Selection/Comparison Analysis:

Multiple evaluation metrics were used to compare the models. Accuracy was shown as an overall score, while macro-averaged precision, recall, and F1-score were reported to account for class imbalance. Confusion matrices were plotted for each model to visualize per-class performance. Multiclass ROC curves were generated using the One-vs-Rest approach and AUC scores were computed for comparing classifier separability. The accuracy comparison shows that Logistic Regression achieved the highest accuracy. Random Forest and Neural Network achieved moderate performance. Lastly, Naive Bayes and KNN showed comparatively lower accuracy.

Technology Stack: Python, NumPy, Pandas, Matplotlib, Seaborn, Scikit-Learn

CSE321: Operating Systems
Project Title: Multithreaded Process Manager Simulator

Developed a multithreaded process manager simulator in C that models how an operating system maintains and synchronizes its internal process table. The project uses Process Control Blocks (PCBs) to represent process metadata and lifecycle transitions, while multiple worker threads concurrently perform operations such as process creation, termination, waiting, and table inspection.
The system was designed to preserve correctness under concurrent access by synchronizing modifications to shared process data and coordinating parent-child interactions during wait and wake-up events. A dedicated monitor thread automatically captures and logs table snapshots whenever the process table changes, making concurrent activity observable in real time without inefficient polling.

System Features:

• Shared process table supporting up to 64 simulated processes
• PCB-driven process representation with PID, PPID, state, exit status, and child tracking
• Support for core process operations: fork, exit, wait, kill, and ps
• Script-based worker threads for concurrent execution of process management commands
• Dedicated monitor thread for automatic process table snapshot logging
• Process lifecycle tracking across running, waiting, zombie, and reaped states

Concurrency & Synchronization:

• Synchronized shared access to the global process table under multithreaded execution
• Coordinated parent-child waiting and wake-up behavior during process termination
• Prevented race conditions during concurrent creation, modification, and cleanup of PCB entries
• Implemented event-driven monitoring to log updates without busy polling
• Simulated OS-style process cleanup and zombie reaping behavior under concurrent workloads

Technology Stack: C, POSIX Threads (pthreads), Synchronization Primitives, File I/O
